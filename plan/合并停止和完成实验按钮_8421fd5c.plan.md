# 合并停止和完成实验按钮

## 分析

当前有两个按钮：

- **停止实验**：在实验运行中可用，停止当前时序，保留会话
- **完成实验**：在会话已创建或等待分析时可用，结束整个会话并保存结果

这两个按钮在 `WAITING_ANALYSIS` 状态下都可用，但功能不同，容易造成用户困惑。

## 方案

合并为一个智能按钮，根据实验状态动态显示和执行：

### 状态逻辑

- **`SEQUENCE_RUNNING`**：显示"停止实验"，执行停止操作
- **`WAITING_ANALYSIS`**：显示"停止并完成实验"，先停止（如果还在运行），然后完成会话
- **`SESSION_CREATED`**：显示"完成实验"，直接完成会话

### 实现步骤

1. **修改UI布局** (`src/views/pages/explosion_page.py:198-210`)

- 移除 `btn_finalize` 按钮
- 修改 `btn_stop` 为智能按钮，根据状态动态更新文本

2. **修改按钮点击处理** (`src/views/pages/explosion_page.py:_on_stop`)

- 根据当前状态判断执行停止还是完成
- 如果正在运行，先停止；如果已停止，则完成会话

3. **修改按钮状态更新** (`src/views/pages/explosion_page.py:_update_button_states`)

- 移除 `btn_finalize` 的状态更新
- 更新 `btn_stop` 的启用逻辑和文本显示

4. **优化完成逻辑**

- 在 `_on_stop` 中集成完成实验的逻辑
- 如果实验已停止且有数据，询问是否完成实验

## 文件修改

- `src/views/pages/explosion_page.py`
- 移除 `btn_finalize` 按钮创建和布局
- 修改 `_on_stop` 方法，集成完成逻辑
- 修改 `_update_button_states` 方法，动态更新按钮文本和状态
- 保留 `_on_finalize_experiment` 方法作为内部辅助方法（可选）

## 优势

1. **简化UI**：减少一个按钮，界面更简洁
2. **逻辑清晰**：根据状态自动判断操作，用户无需选择
3. **避免误操作**：防止用户在运行中误点完成，或在停止后忘记完成
4. **更好的用户体验**：一个按钮完成所有停止/完成操作

## 注意事项

- 需要确保状态判断准确
- 在 `WAITING_ANALYSIS` 状态下，需要先检查是否还在运行
- 完成实验前需要确认对话框，避免误操作
