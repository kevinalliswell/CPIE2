# 相机采集与爆炸性实验专项审查

日期：2026-09-14。范围：CPIE2 收敛 PR #5，以及其固定的外部 FlameKit。没有连接真实相机、继电器、加热器或压力模块。

此前通过的 160 项测试与 Windows 启动检查不能证明高速采集及完整实验流程正确。本次沿实际调用链补查后发现以下缺陷，均建立最小复现和回归。新的候选包应以本轮提交的 Windows CI 为准，9 月 13 日的候选包只保留作历史证据。

## 采集与轮次边界

相机初始化、预览与采集互斥，采集在独立工作线程执行。程序退出先取消操作，线程退出后才释放 SDK 资源；线程仍在运行时保留窗口供重试退出。标定窗口不能与实验采集并行。

喷吹之前发起相机采集请求，并等待第一张有效快照。这个等待发生在时序线程，不会占用 GUI 事件循环。喷吹执行确认后再次核对采集窗口，并要求至少一张有效帧来自确认后才开始的新读取。只有喷前帧、后续持续超时或窗口提前结束，都不能成为有效轮次。这是软件上的检查，不能证明实际曝光与阀门动作精确同步。

每轮采集只允许一次喷吹 ON；配置了重复喷吹时，第二次 ON 会被拒绝，不能复用第一次的采集证明。每次采集使用独立目录，取消后同一轮可重新尝试而不覆盖失败证据。只有时序正常结束、采集与全部落盘成功，才打开该轮的分析窗口。手动拍摄的图像不会自动用于实验。分析取消或保存失败可使用“分析 / 重试本轮”；“放弃本轮”保留原始文件，并允许重新采集同一轮号。

成功提交仅清理当前尝试及其分析输出，保留其他失败尝试。历史记录和永久最大火焰图片不在清理范围。取消、重试和退出均不会把失败测量补成零值或完整结论。

## 当前参数与性能验收

- 仓库当前采集时长为 1 秒，构造参数为分辨率索引 0、曝光 4000 微秒；尚未收到现场相机型号、真实分辨率和目标帧率。这些参数不构成帧率承诺。
- `camera.capture_duration` 传入真实采集 API。历史 `trigger_delay` 从未生效，本轮保留原值但在设置页禁用并明确标注，避免突然改变喷吹与拍摄关系。
- 保留帧内存预算默认 256 MiB，可通过 `camera.max_buffer_mb` 显式配置。单帧原始缓冲约为宽 × 高 × 通道数：MONO8 为 1，BGR8 为 3。1920×1080 单色最多约 129 帧、彩色约 43 帧；超过预算明确失败。预算不包含 SDK、图像转换、编码、Python 对象及其余应用内存。
- 上游 1000 帧回归用模拟 SDK 和真实 JPEG 写入/读回验证顺序、独立快照、完整文件及“采集后才落盘”的边界；它不测量真实相机 FPS 或 SDK/传输链路内部丢帧。
- 当前轮次配置仍为最大 2 轮、阶段 1 轮，未擅自改为 10/5。软件只报告是否完成配置流程，不宣称符合国家标准；正式实验前由现场负责人确认规程和参数。

按 [实机验收记录](HARDWARE_ACCEPTANCE.md) 记录设备帧号/时间戳、实际采集时长、峰值内存、文件数、SDK 丢帧/超时计数及喷吹动作覆盖。必须在目标 Windows 机器与实际相机、串口负载下复验；需要精确同步时采用经验证的硬件触发方案。
