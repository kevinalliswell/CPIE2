## 📋 问题发现与解决

### 关键问题：数据缓存不足导致分析失败

**问题描述**：
- 原设计使用 `deque(maxlen=200)` 缓存温度数据
- 每500ms采集一次 = 只能保存最近 1.67分钟的数据
- 典型实验时长90分钟，着火点在30分钟时检测到
- 实验结束时，着火点数据早已被新数据挤出deque
- 切线法分析时无法获取完整的温度-时间曲线
- **结果**：切线法功能完全失效 ❌

**解决方案**：
- ✅ 从数据库读取完整的实验数据
- ✅ 数据库已在采集过程中持久化所有数据
- ✅ 可获取从实验开始到结束的完整温度曲线
- ✅ 数据完整性得到保证

## 🔧 技术架构

### 数据流设计

```
实验采集阶段：
采集温度 (500ms) 
    ├→ deque(200) → 实时显示 + 实时检测
    └→ 数据库 → 持久化存储（所有数据）

实验结束阶段：
用户点击"停止实验"
    ↓
调用 _analyze_ignition_by_tangent_method()
    ↓
从数据库读取完整数据（get_session_temperature_data）
    ├→ 时间数组：[0, 0.5, 1.0, ..., 5400秒]
    └→ 温度数组×6：[[25°C, 25.5°C, ..., 600°C], ...]
    ↓
遍历6个样品通道
    ├→ 样品1: 切线法检测 → 更新UI/数据库/绘图
    ├→ 样品2: 切线法检测 → 更新UI/数据库/绘图
    ├→ 样品3: 切线法检测 → 更新UI/数据库/绘图
    ├→ 样品4: 切线法检测 → 更新UI/数据库/绘图
    ├→ 样品5: 切线法检测 → 更新UI/数据库/绘图
    └→ 样品6: 切线法检测 → 更新UI/数据库/绘图
```

### 算法流程

```python
for each of 6 samples:
    1. 数据验证（≥50个点，非全0）
    2. 数据平滑（Savitzky-Golay滤波）
    3. 计算一阶导数（温升速率）
    4. 计算二阶导数（加速度）
    5. 识别拐点（加速度显著增大点）
    6. 识别峰顶（温升速率最大值）
    7. 拟合基线（拐点前的线性段）
    8. 拟合峰顶线（峰顶附近的线性段）
    9. 计算交点（两条直线的交点 = 着火点）
    10. 计算置信度（基于拟合质量和斜率差异）
    11. 结果处理（UI、日志、数据库、图表）
```

### 可视化策略

**6个样品的区分方案**：
- ✅ 每个样品使用不同颜色（与温度曲线一致）
- ✅ 基线用虚线，峰顶线用点线
- ✅ 着火点用星形标记
- ✅ 切线延伸到交点附近
- ✅ 文本标注带半透明背景
- ✅ 垂直辅助线半透明显示

## ⚙️ 配置参数

### 启用/禁用切线法

```yaml
ignition_detection:
  enabled: true
  post_analysis: true  # true=启用切线法, false=禁用
```

### 切线法参数

```yaml
tangent_method:
  smooth_window: 11  # 平滑窗口（奇数，默认11）
  smooth_order: 2  # 平滑多项式阶数（默认2）
  baseline_points: 20  # 基线拟合点数（默认20）
  peak_points: 10  # 峰顶拟合点数（默认10）
  min_temp_rise: 20.0  # 最小温升（°C，默认20）
  min_rate_increase: 2.0  # 最小速率增幅（倍数，默认2.0）
  min_data_points: 50  # 最小数据点数（默认50）
```

## 🎯 功能特点

### 双重检测机制

| 特性 | 实时检测 | 切线法分析 |
|------|----------|-----------|
| **触发时机** | 实验过程中 | 实验结束后 |
| **数据来源** | deque缓存 | 数据库完整数据 |
| **数据完整性** | 仅最近1.67分钟 | 整个实验过程 |
| **检测速度** | 快速（200ms） | 较慢（需完整数据） |
| **准确性** | 较高（依赖参数） | 很高（基于物理过程） |
| **标准依据** | 经验阈值 | GB/T 18511-2017 |
| **应用场景** | 过程监控、报警 | 最终报告、存档 |

### 结果对比展示
