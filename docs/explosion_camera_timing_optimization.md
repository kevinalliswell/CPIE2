# 爆炸性实验相机时序

本页于 2026-09-14 按实际实现重写，替代此前关于主线程同步拍摄和 T0 精确同步的描述。专项问题与回归证据见 [相机与实验专项审查](CAMERA_EXPLOSION_AUDIT.md)。

## 当前执行顺序

1. 新一轮启动前确认四路输出 OFF，重新验证最新温度、压力，并建立会话、轮号及尝试标识。
2. 时序线程执行到喷吹动作时，通过直接信号连接启动后台相机工作线程；这个入口不操作 QWidget。
3. 相机取得第一张有效且独立保存的内存快照后，才允许提交喷吹 ON 指令。首帧等待超时或采集失败会中止时序。
4. 喷吹 ON 执行确认后再次检查采集窗口。若采集已结束，即使后台线程仍在编码落盘，该轮也判为无效并执行关断收尾。确认后开始的新读取还必须成功取得至少一张有效帧；仅有喷前图像不能通过。
5. 相机按配置时长采集，结束后编码并核验全部文件。时序正常结束、所有输出关闭且采集保存成功后，才打开属于这次尝试的分析窗口。
6. 全部分析有效、最大火焰图已永久保存且数据库提交成功后，才推进下一轮或保存结论。

单路 `relay_on` 和含喷吹阀的 `relay_multi_on` 都经过同一检查。STOP、取消、采集失败与退出会使旧尝试失效，延迟返回的图像不能进入新轮次。相机初始化、预览、标定与实验采集互斥。

## 参数与同步边界

`camera.capture_duration` 为真实采集时长。保留帧内存默认上限 256 MiB，可通过 `camera.max_buffer_mb` 配置；超预算会失败。日志中的总耗时包括采集与落盘，不能直接作为真实 FPS。

历史 `camera.trigger_delay` 没有实现，本轮保留配置但在设置页标注未启用并禁用编辑，不把旧默认值突然应用到拍摄流程。

首帧与执行确认检查只能验证软件观察到的采集窗口，不能证明阀门实际动作与曝光精确同步，也不能测量 SDK 内部丢帧。现场需要记录相机帧号、时间戳和阀门动作证据；需要精确同步时应使用经验证的硬件触发方案。当前没有真实相机与完整实验验收结果。
