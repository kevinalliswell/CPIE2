# 切线法数据缓存问题分析与解决方案

## 问题描述

当前系统使用 `deque(maxlen=200)` 作为温度数据缓存，用于：
1. 实时绘图显示
2. 实时着火点检测
3. **切线法事后分析** ← 问题所在

## 问题详解

### 时间线分析

```
典型着火点实验（90分钟）：

0min ────→ 30min ────→ 60min ────→ 90min
25°C        350°C       500°C       600°C
            ↑ 着火点
            
数据采集频率：500ms/次 = 120次/分钟
总数据点：90分钟 × 120点/分钟 = 10,800个数据点

deque容量：maxlen=200
保存时长：200点 ÷ 120点/分钟 ≈ 1.67分钟

结果：
- 实验30分钟时检测到着火点（数据在deque中）✓
- 实验继续到90分钟
- 后续60分钟产生 60×120=7,200个新数据点
- 这些新数据不断挤出旧数据
- 实验结束时，deque中只有最后1.67分钟的数据
- 着火点时刻的数据早已被挤出 ✗
- 切线法分析失败或结果错误 ✗
```

### 数据流示意

```
时间 →
[0-28.5min的数据] → 被挤出，丢失 ❌
[28.5-30min的数据] → 着火点附近，被挤出 ❌❌❌
[30-88.3min的数据] → 被挤出，丢失 ❌
[88.3-90min的数据] → 保留在deque中 ✓

切线法需要的数据：
- 基线段：着火前的升温阶段（25-30min）❌ 已丢失
- 着火段：着火点附近（30-35min）❌ 已丢失
- 峰顶段：快速放热阶段（35-40min）❌ 已丢失

实际可用数据：
- 仅有88.3-90min的高温稳定阶段 ✓ 但无用！
```

## 严重后果

1. **切线法分析完全失败**
   - 没有基线段数据 → 无法拟合基线
   - 没有着火段数据 → 无法识别拐点
   - 没有峰顶段数据 → 无法拟合峰顶线
   - 无法计算着火点温度

2. **错误的分析结果**
   - 如果后期温度曲线恰好也有某种变化
   - 可能被误判为"着火点"
   - 得到错误的着火温度（比如580°C而不是350°C）

3. **系统功能失效**
   - 切线法功能形同虚设
   - 无法提供准确的国标检测结果
   - 无法验证实时检测的准确性

## 解决方案

### 方案一：从数据库读取完整数据（推荐）✅

**原理**：系统已经在采集过程中将所有数据保存到数据库，应该从数据库读取完整数据进行切线法分析。

**优点**：
- 数据完整，不会丢失
- 不占用内存（deque可以保持小容量）
- 可以随时重新分析历史数据
- 符合"事后分析"的概念

**实现**：

```python
def _analyze_ignition_by_tangent_method(self):
    """使用切线法重新分析着火点（从数据库读取完整数据）"""
    if self.current_session_id is None:
        self._thread_safe_log("⚠ 无有效会话，无法执行切线法分析")
        return
    
    self._thread_safe_log("🔍 开始切线法分析（从数据库读取完整数据）...")
    
    # 从数据库读取完整的实验数据
    try:
        # 读取该会话的所有温度数据
        session_data = self.db.get_session_data(self.current_session_id)
        
        if not session_data or len(session_data) < 50:
            self._thread_safe_log("⚠ 数据点不足，无法执行切线法分析")
            return
        
        # 构建时间和温度数组
        time_array = []
        temp_arrays = [[] for _ in range(6)]
        
        for record in session_data:
            # 计算相对时间（秒）
            elapsed_seconds = record['elapsed_seconds']
            time_array.append(elapsed_seconds)
            
            # 收集各通道温度
            for i in range(6):
                temp_key = f'sample{i+1}_temperature'
                temp = record.get(temp_key, 0.0)
                temp_arrays[i].append(temp)
        
        time_array = np.array(time_array)
        
        # 对每个通道进行切线法分析
        for i in range(6):
            if len(temp_arrays[i]) < 50:
                continue
            
            temp_array = np.array(temp_arrays[i])
            
            # 使用切线法检测
            result = self.tangent_detector.detect_ignition(time_array, temp_array)
            
            if result is not None:
                # ... 处理结果（与之前相同）
                self.tangent_results[i] = result
                # 更新UI、记录日志、更新数据库、绘制图表
                self._plot_tangent_analysis_from_db(i, result, time_array, temp_array)
            else:
                self._thread_safe_log(f"⚠ CH{i+1} 切线法分析失败")
        
        self._thread_safe_log("✓ 切线法分析完成")
        
    except Exception as e:
        self._thread_safe_log(f"✗ 从数据库读取数据失败: {e}")
```

**需要在数据库中添加的方法**：

```python
def get_session_data(self, session_id: int) -> List[Dict]:
    """
    获取指定会话的所有实验数据
    
    Args:
        session_id: 会话ID
    
    Returns:
        数据列表，每条记录包含时间戳和各通道温度
    """
    try:
        self.cursor.execute("""
            SELECT 
                timestamp,
                pv as furnace_temperature,
                ch1 as sample1_temperature,
                ch2 as sample2_temperature,
                ch3 as sample3_temperature,
                ch4 as sample4_temperature,
                ch5 as sample5_temperature,
                ch6 as sample6_temperature
            FROM ignition_realtime_data
            WHERE session_id = ?
            ORDER BY timestamp ASC
        """, (session_id,))
        
        rows = self.cursor.fetchall()
        
        # 转换为字典列表
        data = []
        start_time = None
        
        for row in rows:
            timestamp = datetime.strptime(row[0], '%Y-%m-%d %H:%M:%S.%f')
            
            if start_time is None:
                start_time = timestamp
            
            elapsed_seconds = (timestamp - start_time).total_seconds()
            
            data.append({
                'timestamp': row[0],
                'elapsed_seconds': elapsed_seconds,
                'furnace_temperature': row[1],
                'sample1_temperature': row[2],
                'sample2_temperature': row[3],
                'sample3_temperature': row[4],
                'sample4_temperature': row[5],
                'sample5_temperature': row[6],
                'sample6_temperature': row[7]
            })
        
        return data
        
    except sqlite3.Error as e:
        self.logger.error(f"✗ 获取会话数据失败: {e}")
        return []
```

### 方案三：混合方案（实时检测时立即执行切线法）

在实时检测到着火点时，立即对当前的数据进行切线法分析：

```python
def _mark_ignition(self, channel, temperature, method):
    """标记着火点"""
    self.ignition_detected_flags[channel] = True
    self.ignition_temperatures[channel] = temperature
    
    # 立即执行切线法分析（趁数据还在deque中）
    if self.config['ignition_detection'].get('immediate_tangent_analysis', True):
        self._immediate_tangent_analysis(channel)
    
    # ... 其他代码
```

**优点**：
- 数据及时，不会丢失
- 实时反馈

**缺点**：
- 此时实验还在继续，温度曲线不完整
- 可能影响实时性能

## 推荐实施方案

**理由**：

3. ✅ 可以随时重新分析
4. ✅ 符合"事后分析"的定位

## 数据流对比

### 当前方案（有问题）
```
采集 → deque(200) → 实时显示
                  → 实时检测
                  → 切线法分析 ✗（数据丢失）

数据库 → 仅存储，不用于分析
```

### 改进方案（推荐）
```
采集 → deque(200) → 实时显示
                  → 实时检测
      → 数据库 → 持久化存储
                → 切线法分析 ✓（完整数据）
                → 历史数据查询
                → 可重复分析
```

## 总结

这是一个典型的**数据生命周期管理**问题：

- **实时数据**（deque）：用于快速访问和显示
- **历史数据**（数据库）：用于持久化和深度分析

切线法作为"事后分析"功能，应该基于完整的历史数据，而不是有限的实时缓存。
