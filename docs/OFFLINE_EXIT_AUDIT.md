# 离线退出审查（2026-09-18）

用户反馈测试电脑未联机、未启动实验，却出现“退出未完成”。截图只能说明资源关闭或保存被阻止，不能单独确定具体分支。

## 复现与原因

在真实主窗口、真实控制器和本地 Modbus 驱动下，仅替换串口客户端：模拟适配器打开成功，所有设备请求抛出实际 `ModbusIOException`。两类实验均为 IDLE、没有当前会话，但旧代码退出失败。原因是 `connected` 只表示串口已打开，退出流程却据此创建控制线程、发送停止指令，等待不存在的设备确认。

单纯启动后关闭、串口打开失败后关闭，以及相机初始化失败且线程已结束后关闭，均可正常退出。相机工作线程尚未结束时保留窗口，线程结束后可重试；本修复未绕过这一资源保护。上述场景均使用模拟边界，未连接实际硬件。

## 修复边界

- 仅完整完成设备初始化和探测、没有任何设备响应、没有发出控制、没有创建轮询或执行线程时，允许跳过退出阶段的硬件关断确认。
- 在驱动请求层立即记录响应，覆盖构造阶段寄存器读取、仅部分继电器读回和 Modbus 协议错误响应；这些都不能当作设备完全离线。
- 写入前记录控制尝试，因为超时不能证明设备未执行；响应和控制记录不会随缓存清空或重连丢失。
- 正常实验停止、启动前 OFF 确认、会话保存和工作线程回收继续使用原有确认流程。

## 回归与验收

`tests/test_offline_shutdown.py` 覆盖两类实验的无连接、端口失败、完全无响应、部分响应、协议错误、超时控制、重连和探测不完整场景。`scripts/smoke_check.py` 保留原启动/恢复/导出/重开检查，并增加第二个真实主窗口通过连接按钮发起离线探测后关闭，确认未启动实验、无控制写入、串口和数据库均释放；输出 `offline_connection_shutdown=true`。

自动化结果以当前 PR 对应提交的日志为准。现场按 [Windows 实机验收记录](HARDWARE_ACCEPTANCE.md) 复验无硬件退出及已联机设备的停止失败重试。旧 `8a67534` 候选包不能用于验证本修复。
